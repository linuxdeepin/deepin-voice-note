# 富文本列表与待办列表 AT 场景规则

本文档用于后续编写 deepin-voice-note 富文本编辑器 AT 用例，覆盖无序列表、
有序列表、待办列表在缩进、反缩进、类型互切、混合嵌套和待办勾选级联中的
产品规则与重点验证场景。

## 1. 适用列表类型

富文本编辑器当前涉及三类列表：

| 类型 | 典型表现 |
| --- | --- |
| 无序列表 | `• item` |
| 有序列表 | `1. item` |
| 待办列表 | `☐ item` / `☑ item` |

三类列表均支持：

- `Tab` 增加缩进；
- `Shift+Tab` 减少缩进；
- 工具栏按钮互相切换列表类型；
- 最多三级视觉层级；
- 在混合嵌套中保持各自列表类型；
- 待办列表支持父子勾选级联。

## 2. 层级规则

### 2.1 最大三级

列表最多支持三级视觉层级：

```text
一级
  二级
    三级
```

规则：

1. 一级列表项按 `Tab`，在有可作为父项的前一个列表项时进入二级；
2. 二级列表项按 `Tab` 进入三级；
3. 三级列表项继续按 `Tab` 时保持三级，不允许生成第四级；
4. 达到三级上限后，图标、checkbox、文本和光标都不能丢失。

AT 需要分别覆盖：无序列表、有序列表、待办列表。

### 2.2 Shift+Tab 不取消一级列表

`Shift+Tab` 只调整列表层级，不负责取消列表。

| 初始层级 | 操作 | 期望 |
| --- | --- | --- |
| 三级 | `Shift+Tab` | 变二级 |
| 二级 | `Shift+Tab` | 变一级 |
| 一级 | `Shift+Tab` | 仍为一级列表项 |

一级列表项执行 `Shift+Tab` 后：

- 无序列表仍显示 `•`；
- 有序列表仍显示数字序号；
- 待办列表仍显示 checkbox；
- 不能变成普通文本；
- 不能导致后续子项游离后无法再 `Tab`。

### 2.3 取消列表

取消列表不通过 `Shift+Tab` 完成。

如需取消当前列表，应通过工具栏点击当前相同列表类型按钮完成。例如光标在
一级无序列表项时，点击无序列表按钮可以取消当前列表上下文。

## 3. 当前项列表类型互切规则

### 3.1 只切换当前光标所在项

列表类型互切以当前光标所在列表项为单位，不允许把整个列表块全部转换。

示例：

```text
☐ first
☐ second
```

光标在 `second`，点击无序列表按钮后，期望：

```text
☐ first
• second
```

不能变成：

```text
• first
• second
```

### 3.2 三类列表两两互切矩阵

AT 至少覆盖以下六组：

| 当前类型 | 目标类型 |
| --- | --- |
| 无序列表 | 有序列表 |
| 无序列表 | 待办列表 |
| 有序列表 | 无序列表 |
| 有序列表 | 待办列表 |
| 待办列表 | 无序列表 |
| 待办列表 | 有序列表 |

每组验证：

- 只转换当前项；
- 父项类型不变；
- 兄弟项类型不变；
- 当前项图标变为目标类型；
- 当前项层级不变；
- 光标不跳行、不丢失。

### 3.3 互切后保持光标位置

列表类型切换后，光标应保持原文本 offset。

英文示例：

```text
☐ first
☐ sec|ond
```

光标在 `second` 中间，点击无序列表后输入 `X`，期望：

```text
☐ first
• secXond
```

中文示例：

```text
☐ 第一行
☐ 你好|世界
```

点击有序列表后输入 `X`，期望：

```text
☐ 第一行
1. 你好X世界
```

## 4. 混合嵌套列表规则

三类列表允许互相嵌套。例如：

```text
☐ parent
  • child
```

```text
• parent
  ☐ child
```

```text
1. parent
  ☐ child
```

规则：

1. 父项保持自己的列表类型；
2. 子项可以切成任意另一种列表类型；
3. 子项 `Tab` / `Shift+Tab` 后仍保持自己的列表类型；
4. 子项不能因 `Shift+Tab` 变成普通文本；
5. 子项图标、数字序号或 checkbox 不能丢失。

### 4.1 待办子项切无序后反缩进

初始：

```text
☐ DCSad
  ☐ 打
```

光标在 `打`，点击无序列表，期望：

```text
☐ DCSad
  • 打
```

继续 `Shift+Tab`，期望：

```text
☐ DCSad
• 打
```

验证点：

- `DCSad` 仍是待办；
- `打` 仍是无序列表；
- `打` 从二级变一级；
- `打` 不能变普通文本。

### 4.2 嵌套互切后再 Shift+Tab

对“三类列表两两互切矩阵”中的每一组，都需要追加验证：

1. 构造父子嵌套；
2. 光标在子项；
3. 子项切成目标列表类型；
4. 对子项执行 `Shift+Tab`；
5. 子项减少一级后仍保持目标列表类型。

## 5. 混合列表中间项反缩进顺序规则

对混合嵌套列表中的中间项执行 `Shift+Tab` 时，应保持用户看到的文本顺序。

初始：

```text
☐ root
  • before
  • active
  • after
☐ next root
```

光标在 `active`，执行 `Shift+Tab` 后，期望：

```text
☐ root
  • before
• active
  • after
☐ next root
```

验证点：

- 文本顺序仍为：`root`、`before`、`active`、`after`、`next root`；
- `active` 变成一级无序列表；
- `after` 保持在 `active` 下一级；
- `root` 和 `next root` 仍是待办列表；
- 所有图标都存在。

不能出现如下错序：

```text
☐ root
  • before
  • after
• active
☐ next root
```

## 6. 游离三级项规则

历史问题场景：

```text
• one
  • two
    • a
    • b
```

对 `a` 连续 `Shift+Tab` 到一级后，`b` 可能被拆成视觉上的“游离三级项”。
当前规则要求：

1. `a` 到一级后继续 `Shift+Tab` 不取消列表；
2. `b` 仍可继续 `Shift+Tab` 降到二级、一级；
3. `b` 也可重新 `Tab` 回二级、三级；
4. 不允许出现 `b` 只能 `Shift+Tab`、不能 `Tab` 的状态；
5. 不允许列表项变普通文本。

AT 操作建议：

1. 构造三层列表，三级包含 `a`、`b` 两项；
2. 光标在 `a`；
3. `Shift+Tab`：`a` 到二级，`b` 仍三级；
4. `Shift+Tab`：`a` 到一级，`b` 仍三级；
5. `Shift+Tab`：`a` 仍一级列表；
6. 光标切到 `b`；
7. 验证 `b` 可 `Shift+Tab` 到二级、一级；
8. 验证 `b` 可 `Tab` 回二级、三级。

三类列表均需覆盖。

## 7. 待办列表勾选级联规则

### 7.1 基础级联

待办列表勾选规则：

1. 勾选父项：所有子项自动勾选；
2. 取消勾选父项：所有子项自动取消；
3. 勾选子项：只有所有直接子项都勾选后，父项才自动勾选；
4. 只勾选部分子项：父项保持未勾选；
5. 不展示半选态；
6. 多级待办从三级向二级、一级逐层冒泡。

部分完成示例：

```text
☐ parent
  ☑ child one
  ☐ child two
```

期望 parent 不勾选。

全部完成示例：

```text
☑ parent
  ☑ child one
  ☑ child two
```

期望 parent 自动勾选。

取消父项示例：

```text
☑ parent
  ☑ child one
  ☑ child two
```

取消 parent 后：

```text
☐ parent
  ☐ child one
  ☐ child two
```

### 7.2 视觉缩进子项也参与级联

由于最多三级限制，部分三级项可能不是 ProseMirror 结构子节点，而是通过
`dvnIndentLevel` 形成的视觉三级项。

AT 和产品行为均以用户看到的视觉层级为准：视觉上属于某个父项的子项，就必须
参与该父项的勾选计算。

重点场景：

```text
☐ top
  ☐ parent
    ☑ child one
    ☑ child two
  ☐ sibling
```

期望：

```text
☐ top
  ☑ parent
    ☑ child one
    ☑ child two
  ☐ sibling
```

说明：

- `child one` 和 `child two` 都勾选后，二级 `parent` 自动勾选；
- 一级 `top` 不自动勾选，因为还有二级 `sibling` 未勾选；
- 即使 `child one` / `child two` 在内部结构上不是 `parent` 的真实子节点，
  只要视觉上是其三级子项，就必须参与 `parent` 的级联计算。

### 7.3 用户反馈链路对应 AT 场景

按以下步骤构造并验证：

1. 创建一个一级待办；
2. 再连续创建一个一级待办；
3. 将第二个一级待办连续按 `Tab` 变成三级待办；
4. 在这个三级待办结尾按 `Enter`，生成第二个三级待办；
5. 将上一个三级待办按 `Shift+Tab` 变成二级待办；
6. 在三级待办基础上继续生成另一个三级待办；
7. 勾选两个三级待办。

期望：

```text
☐ top
  ☑ parent
    ☑ child one
    ☑ child two
  ☐ sibling
```

验证点：

- 勾选一个三级子项时，二级 `parent` 不勾选；
- 两个三级子项都勾选后，二级 `parent` 自动勾选；
- 仍存在未勾选二级 sibling 时，一级 `top` 不勾选；
- 不显示 indeterminate 半选态；
- DOM checkbox 状态与编辑器保存 JSON 状态一致。

## 8. AT 场景矩阵建议

### 8.1 基础缩进矩阵

对无序列表、有序列表、待办列表分别验证：

1. 一级 `Tab` 到二级；
2. 二级 `Tab` 到三级；
3. 三级继续 `Tab` 仍为三级；
4. 三级 `Shift+Tab` 到二级；
5. 二级 `Shift+Tab` 到一级；
6. 一级 `Shift+Tab` 仍为一级列表项。

### 8.2 当前项互切矩阵

覆盖六组互切：

- 无序 -> 有序；
- 无序 -> 待办；
- 有序 -> 无序；
- 有序 -> 待办；
- 待办 -> 无序；
- 待办 -> 有序。

验证当前项、父项、兄弟项、光标和图标。

### 8.3 嵌套互切 + Shift+Tab

每组互切后继续验证：

- 子项保持目标列表类型；
- 子项 `Shift+Tab` 后减少一级；
- 子项不变普通文本；
- 父项类型不变。

### 8.4 混合列表顺序

覆盖：

```text
☐ root
  • before
  • active
  • after
☐ next root
```

对 `active` 执行 `Shift+Tab` 后验证顺序和层级。

### 8.5 待办视觉级联

覆盖视觉缩进形成的三级子项：

```text
☐ top
  ☑ parent
    ☑ child one
    ☑ child two
  ☐ sibling
```

验证 `parent` 自动勾选，`top` 不误勾选。

## 9. 总结原则

列表编辑统一遵循以下原则：

> 以当前光标所在项和用户看到的视觉层级为准。
>
> 三类列表最多三级；`Tab` / `Shift+Tab` 只调整层级，不通过
> `Shift+Tab` 取消列表；列表互切只影响当前项并保持光标；
> 待办勾选级联按视觉父子关系计算，所有视觉子项完成后父项自动完成。
